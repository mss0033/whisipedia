# Audit: wsp-api read paths and the Navigator (2026-10-12)

Scope: `packages/wsp-api` (routes, views, browse, searching, snapshot, zim*, convert, renditions, feed,
offload) and `navigator/src` (pages, core, api client, router, links). Also the contract between
`schemas.py`, `docs/api/openapi.json`, `navigator/src/api/generated.ts` and `wsp-sdk` models.

**Baseline.** Line numbers are for commit `8a6457f` (HEAD), the code the live API at
`127.0.0.1:8737` runs. During the audit another session was changing the working tree: it adds a
stored-original route (`wsp_api/originals.py`, `files.py`), a `Document.original` field, and an
"Original file" panel in `document.ts`. That work targets F1. It is uncommitted and the live server
does not run it. Notes on it are at the end.

**Method.**
- Read GETs against the live API (curl). Nothing was written, and no service was restarted.
- One vitest run from a scratch config that imports the real modules
  (`scratchpad/vt/audit.test.ts`). No source file was edited.
- `wsp_api.openapi_export --check`, `node scripts/gen-api.mjs --check`, and a field-by-field
  comparison of `wsp_api.schemas` with `wsp_sdk.models`.

**Contract check (clean at HEAD).**
- The committed `openapi.json` equals the live `/v1/openapi.json` (version 1.4.0).
- `generated.ts` is up to date.
- Every API model has an SDK twin with the same fields, types and required flags. The SDK also has
  `StreamedChange`.
- The SDK's `doc_path` uses `safe="!'()*"`, which produces the same bytes as `encodeURIComponent`.

## Notes on the uncommitted stored-originals work (working tree, not reviewed as final)

These came up while the files changed under the audit. They are for whoever finishes the work.

- `files.py` and `originals.py` both exist, and `security.py` imports `originals`. If `files.py` is a
  leftover, it is dead duplicate code.
- `FileResponse` streams the file from the NAS on Starlette's shared thread pool. Only `locate()`
  runs in the `nas` offload, so a stalled SMB read during a large PDF transfer takes threads from the
  pool that audit 2026-10-11 #5 meant to protect.
- `preview_lock` is taken *inside* a `nas` worker. Concurrent preview requests each hold a `nas` slot
  while they wait for one decode, which can starve document reads. Take the lock before admission, or
  use a separate one-worker offload for previews.
- `locate()` always reads the *current* document (`documents.get(did)`). In the Time Machine (`?at=`)
  the panel would therefore offer the current edition's file, not the version on screen.
- The preview cache falls back to `/tmp/previews` when `cache_dir` is unset. Prefer refusing to
  preview in that case, or using a private `mkdtemp`.
- F17 (the vault location of `file:` refs) should be fixed in the same change, so that "View Source
  Data" and "Original file" agree.

## Not found to be broken (checked)

- In-page anchors: `#x` → `doc-x`, handled in `onClick`.
- Fragments on `wsp://…#frag`: `scrollTo`.
- Interwiki rewriting for en, top10 languages, Wiktionary and MDWiki.
- `htmlrewrite`: root-relative URLs inside a bundle book, and `srcset`.
- One-segment doc id routing (`RawSegmentRouting`), and the `doc_id_not_encoded` hint.
- Error envelope and `Retry-After` on every 503 path: `busy`, `timeout`, `unavailable`,
  `warming_up`, `zim_unavailable`. All are in the Navigator's `TRANSIENT_CODES`.
- ETag/304 on documents.
- The SSE cursor (`id:` on the last event of a batch; EventSource keeps `lastEventId`).
- The `_DaemonPool` idle accounting overcounts `idle` only after the pool is already at `max`
  threads, so it never under-spawns.
