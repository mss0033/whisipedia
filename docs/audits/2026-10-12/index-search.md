# Audit: index and search path (lexical tiers, Oracle fusion, refresh/resume), 2026-10-12

Scope: `wsp-index` (lexical incl. `_tiers`/`MIN_TIER_HITS`, snippets, refinery id-map sidecars,
docstore, catalog, changefeed, sync, delta, hybrid, suggest, text), `wsp-oracle` (pipeline,
router, vectors), `wsp_core/feedsql.py`, `wsp_cli/indexer.py`. Line numbers refer to `8a6457f`.

Method: code read line by line, plus small reproductions on temporary indexes (scripts summarised
under "Reproductions") and read-only queries against the live API (`127.0.0.1:8737`). Nothing was
written under `~/.local/share/whisipedia` or `/mnt/z`. The only live-store reads were `index-state.json`,
`_SUCCESS.json` files, and `PRAGMA page_count` on `lexical/meta.sqlite` opened with `immutable=1`. One
read was a `SELECT DISTINCT` on `vectors/meta.sqlite` opened with `mode=ro`. Targeted tests:
`test_index_lexical.py` passes (22 tests). None of them covers findings 1, 2, 3, 4, 5, 6 or 7.

Severity: **Critical** = wrong or missing results on common queries in production today.
**High** = wrong results or a corrupt index after a realistic event, or a systematic ranking bias.
**Medium** = wrong under a narrower condition, or a scale or performance defect on the hot path.
**Low** = latent issue or hygiene problem.

## What was checked and found correct

* **Snippets.** Tantivy's `to_html` escapes document text (`<script>` comes back as `&lt;script&gt;`, verified), and the API strips tags before unescaping. The fallback `_lead` escapes too. `snippets()` parses over every route, so a hit chosen by any tier can be highlighted.
* **Ranked window.** The top `rank_depth` hits are re-sorted and the tail keeps BM25 order. Slicing `[offset:offset+limit]` after the re-sort is consistent *within one tier* (finding 6 is about switching tiers).
* **Refinery sidecar writes.** Temporary names include the PID and thread id. `loc` is replaced before `h`, both are fsynced, and the directory is fsynced. Shape and dtype are validated on open.
* **Unsealed directories.** Unsealed generation directories (and set directories) are removed with `rmtree` before a rewrite, so a stale sidecar cannot outlive its `_ids.parquet`.
* **Set composition.** A set's `docs` agrees with its id-index rows, so `RefineryCatalog.random_doc` is uniform and stays in range.
* **`delta`.** The 128-bit id key and 64-bit content prefix work as described. Removal ordering is deterministic, so resume is correct when `old` is set; only the `_orphans` path is wrong (finding 4).
* **Change feed.** Checkpoint and records are written in one transaction. The `ahead of feed` check works. `tail_rows` uses the expression index.
* **Index writer locking.** Both `wsp index build` (`ops.py:71`) and the orchestrator child (`wiring.py:467`) take `HEAVY` then `INDEX`. A second Tantivy writer fails with `LockBusy` (verified), so it cannot corrupt the index.

* **A/B/C (findings 6, 7, 1).** `TantivyIndex(languages=("en","de"))`.
  * A: 35 docs with `"alpha beta " + "filler "*300` and 40 docs titled `"alpha alpha"`. Pages of 10 via `search_hits(offset=o)` give 30 duplicates and 30 docs missing.

  * C: 250 English docs titled `Berliner {i}` and one `de` doc titled `Berliner Mauer`. It is absent from `search_hits(…, 200)`; a single-word query `Mauer` finds it.
